# GLOBAL-POSE-GRAPH-004

## Scope and ownership

This stage adds an independent **offline** global SE(3) pose graph. It does not
subscribe to, publish to, or modify the online eight-state/fixed-lag fusion
backend. The immutable raw scan archive and the original FAST-LIO pose revision
remain the source of truth.

Data flow:

1. immutable raw MID360 archive + original dense pose trajectory;
2. offline keyframes and the existing strict loop frontend;
3. deterministic descriptor retrieval and geometric verification;
4. correlation audit and robust global pose graph optimization;
5. a new traceable corrected-pose revision;
6. deterministic map rebuild through `uf_map_maintenance`.

The first graph node is fixed to remove gauge freedom. Sequential edges come
only from adjacent original keyframe poses. Loop edges are admitted only after
the existing point-to-plane geometric checks (convergence, correspondence,
overlap, reciprocal support, RMSE, and effective rank).

## Graph model and failure protection

Each residual is the SE(3) logarithm of the measured relative transform versus
the transform predicted by the two node poses. Translation and rotation use
separate configured sigmas. Loop residuals use Dynamic Covariance Scaling
(DCS), followed by a post-fit quarantine check.

The optimizer rejects a revision rather than publishing it when any of these
guards fail:

- non-finite node, edge, residual, Jacobian, or solution;
- missing graph rank or unacceptable Jacobian condition;
- solver failure or robust cost increase;
- excessive node correction;
- excessive sequential-edge strain.

Original poses are never overwritten. A successful run writes
`poses_<revision>.csv`, `trajectory_<revision>.csv`,
`keyframes_<revision>.csv`, and `pose_revision_manifest.json` with input and
configuration hashes.

## Correlated loop-edge audit

Multiple loop edges may be generated from adjacent keyframes during one
physical revisit. Treating them as independent evidence over-weights one
event. Two protections are applied before optimization:

1. endpoint/transform clustering retains one representative from near-duplicate
   constraints and records rejected rows as `correlated_redundant`;
2. all distinct retained edges from the same temporally contiguous physical
   revisit episode are scaled by `1/sqrt(N)`, making their aggregate information
   equal to one independent observation while retaining spatial coverage.

The recovered_demo run produced 24 geometrically verified edges. Three were
near-duplicate endpoint/transform constraints; 21 were retained. All 21 belong
to one physical revisit episode, giving an effective independent evidence count
of 1.0. `loop_edge_audit.json` records every selection, episode assignment,
scale, DCS weight, and optimizer/quarantine decision.

An initial unnormalized A/B run is retained under ignored `logs/tmp` as causal
evidence: treating all selected edges independently reduced aggregate residuals
but worsened the representative start/end closure and increased sequential
strain. Episode normalization reversed that behavior without deleting valid
geometric constraints.

## PCL ESF determinism

PCL 1.12 calls `srand(time(nullptr))` inside each ESF computation. Two processes
therefore produced 24 versus 23 verified edges from identical PCD inputs. The
offline frontend now exports a fixed, configurable wall-clock seed only in
`offline_loop_smoke`; online relocalization remains unchanged. With seed 1731,
two complete frontend runs produced byte-identical JSON:

- SHA256: `d00689b252a4b23dd4bb8e28521d650ba50bac9443045723742c4ed79918e685`
- retrieved candidates: 50 in each run;
- geometrically verified edges: 24 in each run.

## Corrected map rebuild

The corrected dense trajectory is generated by interpolating keyframe
corrections onto original scan/point timestamps. The existing per-point deskew
and map-maintenance pipeline then rebuilds from the immutable archive.

- archive: 650 scans, 12,997,632 input points;
- processed: 649 deskewed scans; one unchanged baseline rejection due to
  `missing_left_state`;
- corrected cleaned voxels: 100,362 versus 99,798 original (+0.565%);
- stable wall and stable ground retention: 100% / 100%;
- original/corrected symmetric nearest-neighbor P50/P95/P99:
  4.462 / 25.252 / 67.712 mm;
- voxel Jaccard: 0.92883;
- surface thickness P50: 18.300 to 18.060 mm;
- surface thickness P95: 55.735 to 57.131 mm.

The map therefore changes consistently with the small pose correction and
slightly improves the median local thickness, but it does **not** establish a
global wall-thickness improvement: the P95 thickness is 1.396 mm higher. This
limitation is reported rather than hidden.

Two independent rebuilds produced identical SHA256 values for all products:

- cleaned map: `9dad64c4864d1466350eaa5510b7791002dd7dace72cf3076ebf3157aba85f21`.

## Validation and limitations

The implementation includes unit tests for SE(3), graph construction, fixed
gauge, robust-loop protection, correlation/episode normalization, revision
immutability, file contracts, configuration, map comparison, pipeline
guardrails, loop measurement conversion, and deterministic offline ESF.

Final verification rebuilt `uf_map_maintenance`, `uf_relocalization`, and
`uf_global_pose_graph`. Their leaf suites passed 41 + 54 + 17 tests; colcon's
three wrapper results bring the xUnit total to 115, with zero failures. Python
flake8 (99-column profile), byte compilation, YAML loading, XML validation, and
`git diff --check` also passed. A post-guard graph rerun produced a byte-identical
`optimization_metrics.json` to the reported real-data run.

Limitations:

- recovered_demo has no independent truth, so absolute accuracy is unknown;
- all accepted edges belong to one physical revisit episode; more sessions are
  required to validate multiple independent loops and large drift;
- this stage does not enable online loop closure or feed corrections into the
  online estimator;
- the corrected map does not uniformly reduce all thickness proxies;
- one archive scan lacks a left trajectory state and remains causally rejected.
