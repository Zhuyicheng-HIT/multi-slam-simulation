## 2. 总体目标与当前结论

目标顺序保持不变：

1. 先稳定光流和 GNSS/BDS 数据与伴随计算机融合链路；
2. 再形成 LiDAR、GNSS、IMU、光流的可用紧耦合版本；
3. 随后独立跑通 RGB-D vSLAM；
4. 最后将稳定视觉观测接入统一后端。

当前已经形成第一版在线同窗融合原型：

```text
FAST-LIO 原生点到面残差/J/H ─┐
飞控原始 IMU 预积分 ──────────┤
GNSS/BDS 位置 ─────────────────┼─> 有界滑动窗口 ─> /fusion/unified/odom
下视光流水平位移 ──────────────┘
                  ReliabilityScheduler 控制因子权重、膨胀和开关
```

它已经超过“把多个里程计结果做加权平均”的松耦合方案：LiDAR 使用 FAST-LIO
内部扫描匹配残差导出的正规方程，IMU、GNSS 和光流作为独立因子进入同一窗口。
但当前窗口仍是线性切空间求解器，不是最终的 SE(3) 流形固定滞后优化器；完整
故障矩阵和动态权重消融也未结束。因此，当前版本可用于继续仿真研究和回放，
不能标记为最终可部署的紧耦合版本。

### 3.2 FAST-LIO 原生残差导出

FAST-LIO 补丁导出论文点到面模型对应的原始量：

```text
r_i = n_i^T (p_i^w - s_i)
J_i = [n_i^T, -n_i^T [p_i]_x]
H_k = sum_i J_i^T J_i + 1e-8 I
g_k = sum_i J_i^T r_i
```

验证器从点、平面、位姿和外参独立重建每个残差和 Jacobian，并重新计算
`J^T J`、`J^T r`、对称性和半正定性。已提交测试中，90% 点丢失试验接收并
通过 1404/1404 个数据包；名义、75% 丢点和 90% 丢点的残差与退化评分均有
量化记录。

持久证据：`docs/native_lidar_factor_test_report.md`、提交 `37f3647`。

### 3.3 原生 LiDAR 因子进入统一后端

- 后端将 FAST-LIO 右扰动旋转 Jacobian 转换到后端 RPY 坐标。
- 对于同一状态，`lidar_point_plane` 和 `lidar_pose` 被强制互斥，避免重复使用
  同一份 LiDAR 信息。
- FAST-LIO odometry 仅用于状态初始化和输出连续性；其后验协方差仅做诊断，
  不作为第二个观测因子。
- 原生 LiDAR 正规方程按 `s_L / covariance_inflation` 接受调度。

## 4. 本轮新增但尚未提交的后端改动

### 4.1 GNSS 跳变门控修复

旧逻辑用“当前融合状态与 GNSS 的距离”判断 GNSS 跳变。当 LiDAR 故障先把融合
状态拉偏后，正常 GNSS 会被误判为跳变，造成无法恢复的正反馈失败。

新逻辑只比较当前 GNSS 与最近一次已接受的原始 GNSS fix：

```text
allowed_distance = max(gnss_jump_gate_m, gnss_jump_speed_mps * dt)
reject = norm(p_gnss,k - p_gnss,accepted) > allowed_distance
```

持续跳变期间不更新“最近已接受 fix”，因此跳变结束后能自动回到正常基线。
默认距离门限为 20 m，速度门限为 15 m/s。该改动有独立单元测试，但还需要
重新完成 GNSS 跳变和中断固定航线。

### 4.2 光流偏航耦合实验的处置

本轮尝试把机体系光流位移 `d_body` 写成：

```text
d_map = Rz(yaw) d_body
```

并对 yaw 加一阶 Jacobian。线性化公式和合成单元测试成立，但真实固定航线中，
短积分光流的尺度、积分时序和转弯误差被错误映射到航向，结果明显变差。因此：

- 保留合成因子作为研究入口；
- 新增 `optical_flow_yaw_coupling_enabled`；
- 默认值设为 `false`；
- 默认恢复已验证的地图系水平平移因子；
- 诊断输出 `last_flow_factor_type`，区分 `map_translation` 与
  `body_yaw_linearized`。

该实验不能作为当前默认算法的一部分。以后应在非线性窗口中结合全局位置因子
反复重线性化，而不是在当前切空间窗口里一次性固定 yaw Jacobian。

## 8. 下一次恢复后的保守执行顺序

1. 不改参数，重新跑一次当前默认配置的 80--125 s 名义固定航线，确认原生残差
   包、时间配对、`map_translation` 光流因子、ATE/RPE 和运行实时因子。
2. 用相同路线依次跑 95% LiDAR 丢点、GNSS 50 m 跳变、GNSS 中断和光流质量
   归零；每次只改变一个故障变量。
3. 为四种故障统一记录 before/active/recovery 的评分、权重、膨胀、因子开关、
   原生匹配点数、残差、Hessian 特征值、ATE/RPE 和恢复时间。
4. 在完全相同的 rosbag2 上比较固定权重与 Scheduler 动态权重；只有动态权重在
   至少 GNSS 跳变和 LiDAR 退化中稳定优于固定权重，才形成下一个提交。
5. 将当前切空间后端迁移到 GTSAM IncrementalFixedLagSmoother 或等价的 Ceres
   流形固定滞后窗口，并明确边缘化先验和前端/后端相关性处理。
6. 单独启用 D435i 图像和深度，先建立 RGB-D vSLAM 基线与 `D_V` 评分；视觉
   点云仍按需生成，避免再次拖垮 LiDAR/IMU 基线仿真。
7. RGB-D 独立验收后，只将稳定的相对位姿/重投影或深度平面因子接入统一窗口，
   再进行全模态故障矩阵。

## 9. 当前可用性判断

当前最可靠的成果是：原生 FAST-LIO 点到面残差导出与验证、名义航线同窗消费、
光流/GNSS 伴随计算机链路和因子级调度基础。它已经是一套可继续开发和 rosbag2
评测的紧耦合研究版本。

尚不能宣称“可用紧耦合方案最终完成”，主要阻塞是：

- LiDAR 长时间失效时缺少可靠的航向观测；
- 新 GNSS 门控尚未完成持久化故障矩阵复测；
- 固定权重与动态权重的同袋消融尚未完成；
- 后端仍不是 SE(3) 流形固定滞后优化器；
- RGB-D vSLAM 和最终全融合尚未开始。
