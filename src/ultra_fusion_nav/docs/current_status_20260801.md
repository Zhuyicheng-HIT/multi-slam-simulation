# Ultra-Fusion 仿真当前状态（2026-08-01）

## 结论

当前算法包不能整体称为“可直接上机可用”。应区分三个层级：

1. **完整矩形、普通地图、估计器观察模式：通过。** 起飞、三次 90° 转向、四条边和降落均完成；FAST-LIO 和统一滑窗稳定输出，四源因子进入窗口，且没有使用 Gazebo 真值作为算法输入。
2. **长 S 航线、普通地图：未通过。** 航线本身可以完成，但 LiDAR 前端退化，FAST-LIO 与统一后端都出现米级误差。
3. **ExternalNav 驱动 EKF3：未通过。** 短矩形闭环中飞控在第二航点触发 `EKF3 lane switch 1` 并离开 GUIDED 进入 LAND，不能交给真实飞控控制。

FAST-LIO 的地图状态所有权已完成第一步转移：统一后端确认同时间戳位姿后，
FAST-LIO 才把去畸变点插入局部地图。该模式已通过两次完整矩形回归，并由
平移/旋转一致性门控阻断后端异常状态对前端地图的正反馈。FAST-LIO 内部
ESIKF 目前仍用于预测和点面匹配，因此还不能称为论文目标中的纯 LiDAR 前端。

### 长 S 航线（ExternalNav 不进入 EKF3）

日志：`logs/uf_python_bridge_ab_20260801/`、
`logs/uf_identity_extrinsic_20260801_persistent/`

Python 旧桥和 C++ 直桥的 FAST-LIO 运动 RMSE 分别为约 `2.70 m` 和 `2.90 m`，统一后端约 `2.65-2.95 m`。单位外参与 10° 物理外参结果同量级，因此 10° 外参矩阵不是主因。点云体素重叠中位数约 `0.40-0.44`，明显低于短矩形回归的 `0.61`（历史高质量短基线约 `0.77`）。这是普通地图在长 S 航线上的前端可观测性/动态范围退化，不能靠后端权重宣称修复。

### 时钟对照

日志：`logs/uf_sim_clock_aligned_20260801/`、
`logs/uf_fcu_clock_stamped_20260801/`

- Gazebo 仿真 RTF 下降时，Gazebo 原始时钟与 FCU IMU 时钟不同速，不能简单保留 Gazebo 时间。
- 将每帧点云改成“最新 FCU IMU 时间戳”后，跨域漂移不再累积，但 S 航线误差没有改善（FAST-LIO 运动 RMSE 约 `2.98 m`）。
- 因此该问题是真实存在的时间链路风险，但当前米级误差还不是单一时钟策略造成的。
- C++ 适配器默认恢复为同步快照 + 墙钟重打时间；FCU-IMU 时间戳模式只作为显式诊断开关。

## 当前主要问题

1. **普通地图长距离 LiDAR 前端退化。** 点云结构重复率和体素重叠下降，FAST-LIO 先失去可靠几何约束，统一后端只能跟随错误前端。
2. **ExternalNav 输出仍有短时不连续。** 完整矩形估计器模式下统一后端约 6.7 Hz，ExternalNav 通道约 13.6 Hz，最大间断约 1.05 s；相比旧轮已消除长达 68 s 的断流，但仍不满足 EKF3 可靠接管要求。
3. **在线时空标定尚未锁定。** 当前多次运行均为 `calibration_locked=False`，只能诊断，不能把暂态偏移用于 IMU/外参校正。
4. **光流虽已比早期改善，但受旋转门控、质量和测距有效性影响，不能独立支撑长航线。**
5. **重定位只完成接口与复位路径，尚未完成故障注入后的成功率/恢复时间验证。**

## 代码与验证边界

- C++ Gazebo `LaserScan -> Livox CustomMsg` 适配器已构建，单元测试 5 项通过；实机仍应使用官方 `livox_ros_driver2`，不运行仿真适配器。
- 在线后端原生点到面因子、Jacobian/Hessian 接口和最新帧队列已接入；本轮运行中优化错误为 0，但这不等于轨迹精度达标。
- 后端确认建图模式已经避免 FAST-LIO 后验位姿直接决定后续地图插入；状态所有权扰动测试确认 `native_factor` 模式忽略 `/Odometry`，`native_lidar_pose_fallbacks=0`。
- FAST-LIO 内部 `kf.update_iterated_dyn_share_modified()` 尚未旁路，仍为去畸变和点面匹配提供内部状态；IMU 在 FAST-LIO 与统一后端仍各传播一次。下一轮应先引入统一后端状态种子，再逐步旁路该后验更新。
- EKF3 验证必须保持关闭，直到 ExternalNav 连续性、协方差和跳变门控先达标。当前脚本默认 `VALIDATION_ENABLE_EXTERNALNAV_EKF3=0`。

## 下一步优先级

1. 增加统一后端状态到 LiDAR 前端的显式预测种子接口，并做扰动测试；在不破坏点面匹配的前提下逐步旁路 FAST-LIO 后验校正。
2. 将地图插入从“整帧统一降采样”细化为与原 FAST-LIO 相同的近邻/体素策略，比较匹配数、Hessian、重叠率和算力。
3. 在同一普通地图上做“短矩形 -> 中距离 S -> 长距离 S”的渐进测试，定位前端失锁边界。
4. 给 ExternalNav 增加连续性、跳变、协方差和 reset counter；在 EKF3 闭环前先完成离线 rosbag 回放验收。
